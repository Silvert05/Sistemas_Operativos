01 · Concepto

Un proceso es un programa en ejecución

El programa es la receta (un archivo en disco, pasivo). El proceso es alguien cocinándola: usa memoria, CPU, archivos y dispositivos, y tiene un principio y un fin.

Programa

Pasivo · vive en el disco

Un archivo ejecutable (notepad.exe, /bin/ls). No consume CPU ni memoria mientras nadie lo ejecuta. Permanece hasta que lo borres.

Proceso

Activo · vive en la RAM

Una instancia en ejecución: tiene su memoria, su estado, su contador de programa y un PID. Nace, vive y termina. De un mismo programa pueden existir varios procesos.

03 · Ciclo de vida

Estados y PCB

Mientras vive, un proceso cambia de estado. El sistema operativo guarda todo lo necesario para pausarlo y retomarlo en una ficha: el PCB (Process Control Block).

Nuevo

Se está creando

El SO le asigna PID y prepara su PCB y su memoria.

Listo · Ejecutando

Quiere / tiene la CPU

Listo espera turno. Ejecutando usa la CPU (uno por núcleo).

Bloqueado · Terminado

Espera / ya acabó

Bloqueado espera E/S o un evento. Terminado libera sus recursos.

04 · Creación y terminación

Procesos que crean procesos: fork()

Todo proceso nace de otro (su padre), así que forman un árbol. En Linux se crea con fork(); en Windows con CreateProcess(). Al terminar pueden quedar zombis o huérfanos.

// Antes de fork() hay UN proceso pid_t pid = fork(); // Ahora hay DOS: padre e hijo if (pid == 0) { printf("Soy el HIJO\n"); // fork devolvió 0 } else if (pid > 0) { wait(NULL); // el padre espera al hijo printf("Soy el PADRE\n"); // pid = PID del hijo } else { perror("fork"); // -1: error }
Retorno de fork()

0 → eres el hijo · PID → eres el padre · -1 → falló.

Zombi

Ya terminó, pero su padre aún no hizo wait(): solo queda su PCB.

Huérfano

Su padre terminó antes: init/systemd lo adopta.

05 · Cambio de contexto

Guardar uno, cargar otro: el cambio de contexto

Para que varios procesos compartan la CPU, el SO guarda el estado del que sale en su PCB y restaura el del que entra. Es como marcar la página de un libro antes de leer otro. Mientras tanto, nadie avanza: es tiempo perdido.

06 · Planificación de la CPU

¿A quién le toca la CPU? Los algoritmos

El planificador de corto plazo elige entre los procesos listos. Cada algoritmo prioriza algo distinto: simplicidad, espera mínima, justicia o urgencia.

FCFS

Primero en llegar

Simple. Sufre el efecto convoy: un proceso largo retrasa a los cortos.

SJF / SRTF

El más corto primero

Mínima espera promedio. Necesita conocer la ráfaga; los largos pueden sufrir inanición.

Round Robin

Turnos (quantum)

Justo y con buena respuesta. Un quantum muy chico genera muchos cambios de contexto.

Prioridades

Primero lo urgente

Flexible. Riesgo de inanición; se corrige con aging (envejecimiento).

Métricas. Retorno = fin − llegada · Espera = retorno − ráfaga · Respuesta = primera ejecución − llegada. Ráfaga: tiempo de CPU que necesita el proceso.

07 · Hilos

Hilos: procesos ligeros

Un hilo es una línea de ejecución dentro de un proceso. Los hilos de un proceso comparten código, datos y archivos, pero cada uno tiene su propia pila y sus registros.

Proceso

Unidad de propiedad de recursos: memoria, archivos, PID. Aislado de los demás. Crearlo es costoso.

Hilo

Unidad de ejecución: PC, registros y pila propios; comparte el resto con su proceso. Crearlo es barato, pero un error puede tumbar a todos.

09 · Sincronización

Cuando compiten: carreras e interbloqueos

Si varios procesos o hilos tocan datos compartidos, el resultado puede depender del orden en que se intercalen. La sección crítica es el código que toca esos datos: solo uno puede estar dentro a la vez (exclusión mutua).

Inanición

Un proceso espera indefinidamente porque otros siempre pasan delante. Solución: aging.

4 condiciones (Coffman)

Exclusión mutua · retención y espera · no apropiación · espera circular. Si falta una, no hay interbloqueo.

Herramientas

Mutex, semáforos, monitores y variables de condición.
